# Wiggle Web 확정 제품 결정

## 2026-10-14 PDF 저장 전 전체 그림 준비 확인

- 여러 학생의 PDF에서 그림 대신 로딩 표시가 남는 제보에 대해, 전체 그림·글꼴 준비 후 인쇄하고 실패한 쪽과 재시도를 안내하는 수정 방향을 설명했다. 사용자: “그렇게 pr 날려”. 이 수정과 기능 브랜치 push·PR 제출을 승인했다.
- 저장된 학생 그림책과 이미지 원본은 변경하지 않는다. 이미지가 누락된 상태의 PDF 저장을 막고 로딩 진행·실패를 알려 준다. main 병합·운영 배포는 사용자가 진행한다.

## 2026-10-12 그림책의 누적 이미지 60개 제한 제거

- 후속 사용자 확정: “학생들한테 직접적으로 보이는 그림에 제한이 없어야해. 지금은 20명 정도만 사용 중인거니까 최대한 많은 그림을 각각의 학생들이 쓸 수 있게 반영해 줘.” 책 누적 자산뿐 아니라 한 쪽의 50개 요소 상한도 제거한다. 새 그림·붙여넣기·복제·양식·PDF 배경 편집이 그림 수 때문에 막히지 않게 한다. 개수 상한을 더 큰 숫자로 대체하지 않는다.
- 파일당 용량·문서 전송 바이트·PNG 검사·소유권·요청 속도 보호는 유지한다. 학생별 총 이미지 개수 할당량은 두지 않고, 이미지가 많은 책에서 업로드·저장의 반복 조회를 줄인다. 기존 책과 원본 파일을 삭제하거나 자동 정리하지 않는다.
- 사용자: “지금 학생들이 그림책에서 그림을 넣고 있는데 그림을 60개 이상 못넣게 되어 있대. 그리고 24명 중 딱 1명만 그림을 1개밖에 못넣는다는데 무슨 문제일까? 60개 이상 못넣게 되어 있는 제한을 좀 없애야할 거 같은데 가능해?”
- 학생 업로드 API의 책 한 권당 누적 이미지 60개 제한을 제거한다. 개수를 다른 숫자로 올리는 방식이 아니라, 보관 파일 수로 새 그림·내 그림 가져오기·누끼 수정본을 막지 않는다.
- 기존 책·삭제한 그림의 보관 원본·누끼 이전 파일을 지우거나 재작성하지 않는다. 파일당 크기/PNG 검사·소유권·분당 요청 제한은 유지한다. 한 쪽의 요소 수 제한도 위 후속 결정에 따라 제거한다.
- 특정 학생의 1개 증상은 오류 문구와 책 주소를 요청했다. 동일한 증상을 만들 수 있는 누적 자산 제한은 확인했으나 실제 학생의 원인으로 단정하지 않는다.

## 2026-10-03 태블릿 목록 정렬·이야기 칸 위쪽 고정

- 사용자: “모든 것들이 아이패드나 갤럭시탭에서 형식이 이쁘게 나와야만 해. 위 이미지 화면에서 패드에서는 정돈이 안된 상태로 나오니까 확인해보고 깔끔하게 나올 수 있게 수정해.” 학생 홈의 만드는 중/완성된 그림책은 같은 폭·표지 크기·버튼 정렬을 사용하고, 세로·가로 태블릿과 긴 제목에서도 정돈되게 표시한다. 그림책 보관함·편집·미리보기도 함께 실측한다.
- 사용자: “이야기 칸 위치와 이야기 칸 높이가 왜 둘 다 있어? 기능이 비슷해보이는데 한 개만 있어도 될 거 같은데? 이야기 칸이 위아래로 움직이면 안되고 원래처럼 윗쪽에 고정을 시켜.” 세로 위치 도구를 제거하고 높이 조절만 남긴다. 기본/추가 이야기 칸은 위쪽에서 시작하며 높이는 아래로만 늘어난다. 글자의 칸 안 세로 정렬은 기존 요청대로 유지한다.
- 이미 저장한 학생 책의 좌표를 로드 시 재작성하지 않는다. 겉표지·속표지·작가의 말의 각 글칸 위치도 양식대로 보존한다. 이번 변경은 목록과 편집 도구를 정리하며 데이터 마이그레이션을 하지 않는다.

## 2026-10-03 그림책 전체 화면 제거·세로 스크롤 (후속 정정)

- 사용자: “아이패드나 갤럭시 탭같은 패드에서 사용할 때는 첫 번째 이미지에 있는 도구들을 아예 안보고, 그림책만 보이게 하고 싶어. 그냥 스크롤을 내려서 밑으로 움직일 수 있게 해주자. 전체 화면 기능은 그냥 없애도 돼.”
- 그림책 편집의 전체 화면 버튼과 전환을 제거한다. 제목·저장·미리보기·완성 줄과 가로 도구 줄은 아래로 스크롤하면 위로 사라지고, 위로 돌아가면 다시 사용할 수 있다. 책을 누르거나 편집해도 별도 화면 전환을 하지 않는다.
- 기존 좌우 쪽 목록/책/선택 도구 배치와 가로 도구 스크롤은 유지한다. 책의 빈 곳·선택하지 않은 그림에서는 손가락으로 세로 스크롤하고, 선택한 그림의 이동·크기 조절은 유지한다. 기존 그림책 데이터와 저장 형식은 바꾸지 않는다.

## 2026-10-03 그림 붙여넣기·배경 제거·크기 조절

- 사용자: “다른 곳에서 Ctrl+C한 그림을 그림책에다가 Ctrl+v로 붙여넣기를 할 수 있게 해줘야해. 그리고 애들이 그림을 넣었을 때, 누끼를 좀 더 쉽게 딸 수 있게 수정해. 애들이 그림 크기를 자유롭게 못만지더라.”
- 그림책 편집기에서 실제 이미지 클립보드를 Ctrl+V/⌘V로 붙여넣고 기존 텍스트 붙여넣기는 유지한다. 이미지 추가·저장은 기존 자산 경로를 사용한다.
- 그림은 일반 내지에서도 종이 전체를 사용해 움직이고 크기를 바꾼다. 기존 그림의 위치는 열 때 바꾸지 않는다. 큰 손잡이와 작게/크게 버튼, 비율 유지 및 독립 가로·세로 조절을 제공한다.
- 도구창을 닫아도 선택된 그림의 손잡이를 유지해 작은 화면에서 그림을 직접 조절할 수 있게 한다. 선택 해제는 별도 버튼으로 제공한다.
- 배경 제거는 선택 도구 앞에서 바로 열고 자동 결과를 먼저 확인한다. 되돌리기·지우개·다시 살리기를 제공하고 ‘이 그림 넣기’를 눌렀을 때만 새 이미지로 저장한다. 원본 이미지 객체는 덮어쓰지 않는다.

## 2026-10-03 그림책 편집·양식·수정본 (사용자 화면 제보)

- 학생 그림 자리의 새 그림은 모든 화면에서 맨 왼쪽 첫 카드다. 새 그림책 만들기도 첫 진입 카드로 둔다.
- 이야기 칸을 누르면 그 칸의 전용 도구를 열어 글자 크기·색·정렬을 바꾼다. 글자를 세로 중간에 놓을 수 있어야 한다. 글이 가득 찼다는 경고는 해당 쪽에만 표시한다.
- 최초의 1~5쪽 고정 양식 요청은 같은 메시지의 마지막 정정으로 대체됐다. 사용자: “아니다. 내가 말한 양식들을 아이들이 직접 선택할 수 있게 하자.” 겉표지·속표지·작가의 말·내지·자유 양식을 선택하며, 표지에는 제목과 `글 / 그림` 이름 칸을 둔다. 명단의 실명을 자동으로 복사하지 않고 아이가 이름을 직접 입력한다. 5쪽 전용 양식이나 강제 페이지 삽입은 없다.
- (같은 날 후속 정정) 편집 전체 화면은 제거하고 세로 스크롤로 도구를 화면 밖으로 올려 책을 크게 본다. 미리보기는 겉표지와 펼친 내지를 책장 넘김 표현으로 읽는다.
- 교사가 가져온 PDF도 같은 편집기에서 글·그림·양식·쪽 순서 등을 고칠 수 있어야 한다. 현재 PDF는 페이지 이미지로 저장되므로 원본 안의 개별 글자 수정 범위는 질문 중이다.
- 만드는 중인 책과 완성 책을 구분하고 책 전체를 복제한다. 원본을 남겨 피드백 전후의 1차·2차를 비교할 수 있어야 한다. 복사본은 새 ID의 초안이며 제목을 직접 바꿀 수 있다.
- 사용자 최우선 지시: “절대로 지금까지 작업된 학생들의 그림책은 유지가 되어야해. 절대 뭔가를 없애면 안돼.” 자동 데이터 마이그레이션·원본 삭제·로드 시 글 합치기/잘라내기/좌표 재배치는 하지 않는다. 운영 DB·버킷은 직접 변경하지 않는다.
- 사용자가 제보한 서비스 주소는 `https://www.kkumtle.app/student`다. 기존 Vercel 주소의 이력은 보존한다.

## 2026-09-28 그림책 수량·태블릿 편집·안내

- 학생 홈의 그림책 수량과 실제 표시되는 책을 일치시킨다. 홈의 2권 미리보기 제한을 제거하고 받은 그림책을 모두 표시한다.
- (같은 날 사용자 정정) 그림책 편집의 기존 좌우 배치를 유지한다. 요청한 스크롤은 상단 도구 모음의 **가로 스크롤**이다. 태블릿에서 쪽 목록을 위로, 꾸미기 패널을 아래로 옮긴 구현은 취소한다.
- (같은 날 추가 정정) “스크롤 바가 보여야지 ;;” — 도구 모음 아래에 트랙과 손잡이가 평소에도 보이는 가로 스크롤바를 둔다. 스와이프만 가능한 상태나 기기가 자동으로 숨기는 기본 스크롤바만으로 완료 처리하지 않는다.
- (같은 날 모양 정정) “스크롤바가 아니라 진행바같잖아. 스크롤바처럼 보이게 이쁘게 잘해봐” — 초록색 채움 막대 모양을 없애고 이동용 레일·손잡이로 구별되는 스크롤바 디자인으로 다듬는다.
- 손잡이를 끄는 것뿐 아니라 **도구 버튼이 있는 줄을 직접 좌우로 스와이프**해도 움직여야 한다. 스와이프 중에는 버튼 기능이 실행되지 않아야 한다.
- `그림 꾸미기`는 오른쪽에 두고 그림 첨부·선택 시에만 표시한다. 선택 해제·다른 쪽 이동 시 닫는다. 사용자 원문: “그냥 좌우로 움직일 수 있게만 해주면 되고. 우측에 있던 그림 꾸미기는 그대로 그림 꾸미기로 냅둬야지 … 그림을 첨부하거나 클릭해서 그 그림에 대한 수정을 할 때만 나오도록 해.”
- 그림책의 `저장`은 `임시 저장`, `완성하기`는 `그림책 완성하기`로 표기한다. 임시 저장한 제목·글·그림은 같은 학생으로 다시 로그인해도 남아 있어야 한다.
- 교사 작품 보관함의 `모든 학생`, `전체 그림 보기`, `전체 그림책 보기`는 같은 글꼴·크기·굵기를 사용한다. 완성 화면의 `첫 화면으로`와 `편집으로 돌아가기`도 글꼴과 정렬을 맞춘다.
- PDF 가져오기는 학생의 그림책 완성 여부와 관계없이 교사가 준비한 PDF로 그림책 제작을 요청하는 기능임을 안내한다.
- 최신 `yonghwan86/wiggle_web` main에서 작업하고 `qudcks1940` 계정의 기능 브랜치를 push하여 PR을 제출한다. 운영 main push·병합은 사용자 실행이다.

## 프로젝트와 제품 중심

1. 기존 Flutter 저장소를 수정하지 않고 `wiggle_web`을 별도 Git·GitHub 저장소로 운영한다.
2. (2026-08-23 확정) 이후 웹 개발은 신규 팀 저장소 `https://github.com/wwwiggle/new_wiggle`에서 계속한다. 기존 `yonghwan86/wiggle_web`은 Vercel 연결을 실제로 바꾸기 전까지 현재 운영 배포 원본으로 보존한다.
3. (2026-08-23 확정) 신규 팀 저장소는 `main`을 기본 브랜치로 사용하고, 현재 검증 브랜치 `codex/updated-design-storybook`을 Pull Request로 `main`에 병합한다. 이후 기능도 직접 `main`에 쌓지 않고 기능 브랜치와 PR 흐름을 사용한다.
4. 제품 중심은 `AI 그림 학습 도구 + 교실 창작 코칭 플랫폼`이다.
5. 이야기·가족 공유·구독은 그림 학습과 교사 코칭 이후 단계적으로 확장한다.
6. AI는 그림을 대신 완성하거나 평가하지 않는다. 부르는 방식은 2026-09-12에 바뀌었다 — 아이가 부를 때에 더해 **몽그리가 먼저 말을 거는 자동 개입**을 둔다(같은 절 6-1항). AI 도우미의 이름은 `몽그리`다(2026-09-07 사용자 결정, 옛 이름 `그리미`). 예외: 완성한 그림책에 대한 **교사용 루브릭 평가**는 2026-09-09 별도 요청으로 두며, 아이 화면이 아니라 교사 화면에만 나온다.
7. 점수·순위·재능 진단·공개 SNS 경쟁은 만들지 않는다. 완성 그림책의 교사용 루브릭 채점·피드백 PDF만 예외다(2026-09-09 사용자 요청).
8. 핵심 학생 대상은 **초등학교 3~6학년**이다(2026-09-12 사용자 정정. 2026-09-09에 1~5학년으로 잡았던 것을 바꾼다). 글을 읽을 수 있는 나이지만 읽기 부담은 낮춘다 — 핵심 행동은 그림·아이콘·큰 터치 영역으로도 알 수 있어야 한다(브라우저 읽어 주기 버튼은 2026-09-09 사용자 지시로 제거).

## 학생 입장과 기록

1. 수업 코드와 학급 QR은 학급 입장 수단이며 학생 신원이나 작품 접근 권한이 아니다.
2. 작품과 과정 기록은 서버가 발급한 익명 학생 ID에 저장한다.
3. 학생 이메일·학교명 없이 참여한다. 학생 실명은 교사가 만든 학급 명단에만 두고 그 학급 담임 교사에게만 보여 준다(2026-09-07 사용자 결정). 이유: 교사가 15명 남짓한 학급을 직접 열고 명부와 대조하려면 부르는 이름만으로는 부족하다는 현장 의견. 학생 화면·가족 공유·그림책·AI 요청에는 실명을 싣지 않으며, 학급을 지우면 명단도 함께 지운다.
4. (2026-09-09 결정, 2026-09-12 개정) **입장은 두 단계다: 반을 정하고 → 아이 참여 코드 네 자리.** 반은 **학급 QR이 기본**이고, QR을 못 쓸 때 대문에서 4자리 수업 코드를 넣는다. 참여 코드는 여섯 자리에서 **네 자리로 줄였다**(2026-09-12 사용자 결정) — 여섯 자리는 저학년이 누르기 벅찼다. 종전 문장은 다음과 같다. ~~입장은 수업 코드 → 아이 참여 코드 6자리, 두 단계다.~~ 교사가 명단을 만들면 자리(번호·실명)마다 무작위 참여 코드가 붙고, 아이는 대문에서 4자리 수업 코드나 학급 QR로 반을 확인한 뒤 자기 참여 코드 하나만 누르면 바로 자기 도화지로 들어온다. 처음 들어올 때만 동물 하나를 고르고, 별명은 그 동물의 기본 별명이 자동으로 붙는다(아이가 글자를 치지 않음). 동물을 고르면 곧바로 빈 도화지가 열린다(학습 과정 0항). 이유: 번호 + 그림 비밀번호 3개는 1~2학년이 매번 기억해야 해서 너무 어려웠다("지금 너무 어려워서 변경할려고"). 코드는 종이에 적혀 있고 코드가 곧 그 아이의 자리라, 다음 회차에 같은 코드를 넣으면 같은 학생 ID로 돌아오므로 아이가 자기 지난 그림을 찾을 필요가 없다.
4-2. (2026-09-13 사용자 결정) **입장 화면 두 곳에 앱 안 QR 찍기를 둔다.**
   - 첫 화면(수업 코드 입력): `QR로 찍기`. 반 QR을 찍으면 그 반 참여 코드 화면으로, 아이별 쪽지 QR을 찍으면 키패드 없이 바로 들어간다.
   - 참여 코드 화면: `내 쪽지 QR로 찍기`. 아이별 쪽지 QR만 쓸모가 있다(반 QR에는 참여 코드가 없다고 안내한다).
   - **쪽지 QR은 아이마다 다르다.** `<반 주소>/join/<수업 코드>#entry=<참여 코드>`. 선생님 화면·전자칠판의 큰 QR은 반 QR 그대로다 — 한 아이 코드를 반 전체에 띄우면 안 된다.
   - 참여 코드는 쿼리가 아니라 **주소 조각(`#`)**에 담는다. 조각은 서버로 가지 않아 접속 로그·Referer에 남지 않고, 입장 화면이 읽자마자 `history.replaceState`로 주소창·방문 기록에서 지운다.
   - 스캐너는 찍은 주소를 따라가지 않는다. 네 자리 숫자 둘만 꺼내 우리 주소로 다시 만든다. 형식이 조금이라도 다르면 거절한다.
   - 이유와 위험: 저학년이 네 자리를 누르기 어렵다. 쪽지 한 장이 입장 수단이라는 점은 종전과 같다 — 같은 쪽지에 참여 코드가 이미 글자로 인쇄돼 있기 때문이다(5항). 코드를 새로 뽑으면 옛 QR도 함께 죽는다(QR이 같은 코드를 담으므로). 무차별 대입은 기존 학급+IP 제한이 그대로 막는다. 사용자에게 "쪽지 한 장이 그 아이 그림을 여는 열쇠가 된다"는 위험을 알린 뒤 결정했다.

## 캔버스와 입력

1. 패드 사용을 중심으로 펜 입력 모드를 기본값으로 한다.
2. 손가락 그리기는 사용자가 명시적으로 선택할 때만 활성화한다.
3. 펜 모드에서 손바닥과 일반 터치는 그림을 방해하지 않아야 한다.
4. 두 손가락 제스처는 확대·축소와 화면 맞춤에 사용한다.
5. 모두 지우기는 확인 후 한 번에 지우며 한 번의 되돌리기로 복원할 수 있어야 한다.
6. 지우개는 실제 지워지는 범위를 네모 커서로 보여준다.
7. 색상은 갈색·민트색을 포함해 충분히 제공하고 선택한 색의 이름을 표시한다.
8. 선 굵기는 현재 선택된 펜을 다시 누르면 그 펜 왼쪽에 펼쳐지는 드래그 슬라이더로 조절한다(2026-08-30 사용자 변경 결정, 2026-09-07 시안으로 확인). 화면 바깥·다른 도구·Esc로 닫는다. 이유: Freeform식의 좁은 세로 플로팅 도구 레일과 넓은 도화지를 유지하면서 굵기를 바꾸기 위해서다. 이 슬라이더는 떠 있는 레일을 쓰는 넓은 화면(가로 900px·세로 600px 이상)에만 둔다. 휴대전화와 세로가 짧은 화면은 2026-08-18의 5단 점 버튼을 그대로 쓴다 — 좁은 화면에서는 팝오버가 도화지를 가리고 44px 터치 목표를 깨기 때문이다. 점은 현재 선택한 색으로 칠하고 지우개 선택 시에는 잉크색으로 남긴다.
9. 도화지는 화면을 가득 채운다(2026-09-07 사용자 결정). 새 작품은 첫 획을 긋기 전까지 그릴 수 있는 넓이의 비율을 따라가고, 한 획이라도 그으면 그 비율로 굳는다 — 그린 뒤에 비율을 바꾸면 이미 그린 선이 늘어난다. 이유: 그리기 화면 시안의 넓은 도화지를 그대로 쓰기 위해서다. 비율은 문서에 함께 저장하며, 세로 값이 없는 기존 작품은 예전처럼 정사각(1024×1024)으로 남는다 — 좌표가 x·y 모두 0~1로 정규화돼 있어 비율을 바꾸면 이미 저장한 아이 그림이 찌그러지기 때문이다. 점선·시범 안내 좌표는 정사각 기준으로 그려 둔 것이라 도화지 가운데의 정사각 영역 안에 넣어 동그라미가 타원이 되지 않게 한다.

8. 메인 화면의 제목·문구·학생 안내·4자리 수업 코드 입력 카드·그림책 색감을 유지한다. 2026-09-06 사용자가 화가 오리 중심의 전시관 시안을 선택하고 사이트용 개별 에셋 제작을 요청하여, 메인의 교실 그림 고정 원칙은 갱신한다. 기준은 `docs/design-assets/gallery/selected-reference.png`이며 오리·전시 그림 3종과 제품 차별점 영역을 포함한다. 이유: 화가 오리를 브랜드 중심으로 보이고 제품의 특징을 설명하기 위해서다. 2026-09-07 사용자 지시로 실제 대문 라우트를 이 시안으로 구현했다. 그림은 개별 에셋으로 배치하고 문구·버튼·수업 코드 입력칸은 HTML로 만들며, 하단에 `모두 다른 답`·`AI는 대신 그리지 않아요`·`비교보다 발견` 소개 영역을 둔다. 은퇴한 것은 대문 그림 하나에 HTML을 얹던 단일 무대 방식이며, 4자리 코드 입장과 교사 수업 열기 동작은 그대로다.
9. `examples/KakaoTalk_20260817_182137151.jpg`, `examples/KakaoTalk_20260817_185428983.jpg`, `examples/KakaoTalk_20260817_194906484.jpg`는 각각 메인 화면, 학생 프로필 생성 화면, 학생 홈의 확정된 넓은 화면 시안이다. 메인 에셋에는 위 8번의 최신 결정을 우선한다. 학생 프로필 생성·학생 홈은 현재 구현이 기존 시안의 구성·비율·위계를 제대로 재현하도록 수정한다.
10. 위 세 화면에 대한 사용성 피드백은 시안을 바꾸라는 새 디자인 요구가 아니라, 현재 코드에서 시안과 다르게 구현된 배치·크기·간격·잘림·음성 위치·반응형 문제의 수정 목록으로 사용한다.
11. 시안은 시각적 구성 기준이며 이후 확정된 기능 결정을 되돌리지 않는다. 수업 코드는 4자리를 유지하고, 학생 프로필이 있는 학급의 `새로 시작하기` / `내 그림 이어가기` 분기와 기존 학생의 `동물 + 별명 + 그림 비밀번호 3개` 재입장 흐름을 적용한다.
12. 설계 설명용 목업의 `우리 반 20명 목록이나 다른 학생의 그림은 보여주지 않아요`와 같은 주석은 실제 아이용 제품 문구로 사용하지 않는다.
13. 학생 홈 상단의 선생님 말씀 버튼은 💌 아이콘을 쓴다. 넓은 화면에서는 `💌 선생님 말씀`처럼 글자 라벨을 함께 보여주고(헤더의 아이콘+글자 버튼 규약), 휴대전화 폭에서는 44px 정사각 아이콘 버튼으로 접는다. 👩‍🏫 이모지는 버튼 아이콘으로 쓰지 않는다 — Windows에서 조합 이모지가 깨져 보이고 버튼의 용도가 읽히지 않는다(2026-08-18 사용자 결정). 말풍선·이력 안의 말하는 주체 표시로는 계속 쓴다.
14. 학생 홈 하단 선반 카드는 시안대로 아이콘·제목·상태 칩을 칸 중앙의 한 덩어리로 배치하고, `활동 고르기` 카드에는 상태 칩을 붙이지 않는다.
15. 앱의 기본 색은 파란색이 아니라 초록색이다(2026-09-07 사용자 결정, 2026-09-09 최신 main에 적용). 화면·버튼·배경 그림의 파란 계열은 초록·크림 팔레트로 맞추고, 브랜드 로고·앱 아이콘·오리 몽그리의 파란 모자·스카프와 그리기 팔레트의 물감 색은 바꾸지 않는다.
16. `/join`의 수업 확인 대기·실패 화면은 `docs/design-assets/entry-green/reference/approved-green-palette-fixed.png` 교실 시안을 따른다. 넓은 화면은 팔레트를 잡은 오리 완성 장면을 배경으로 쓰고 문구·버튼은 HTML로 올리며, 좁은 화면은 크림 배경과 독립 오리로 바꾼다. 도움 버튼 문구는 기존 `선생님 불러요`를 유지한다.

## 그림책 만들기

1. 외부 Canva 편집 화면을 붙이지 않고 Wiggle 안에서 직접 동작하는 그림책 편집기를 사용한다(2026-08-20 사용자 결정).
2. 각 쪽의 이야기 글은 하나만 두며 페이지 위쪽 가운데의 고정 영역에서만 편집한다. 글 요소를 추가·복제·이동·회전하는 기능은 제공하지 않는다(2026-08-21 사용자 결정). 이유: 초등학생이 글 배치를 따로 조정하지 않고 이야기 작성에 집중하게 한다.
3. 학생의 완성 그림과 새 그림은 글 아래의 지정된 그림 영역 안에서만 추가·이동·크기 변경·회전할 수 있다. 그림과 선택 박스는 같은 종횡비를 유지하고 지정 영역 밖으로 나갈 수 없다(2026-08-21 사용자 결정). 원본 이미지의 흰색·투명 빈 캔버스는 선택 박스에 포함하지 않고 실제로 보이는 그림의 픽셀 경계에 맞춘다. 원본 자산은 보존하고 요소별 내용 경계를 저장하며, 자동 계산과 `빈 여백 없이 맞추기`를 함께 제공한다(2026-08-23 사용자 결정).
4. 사용자가 올린 배경 이미지는 페이지 전체를 채우는 배경층이 되며, 그 위에 고정 이야기 글과 그림이 올라간다. 배경색은 이미지가 없거나 투명한 부분의 바탕으로 유지한다(2026-08-21 사용자 결정).
5. (2026-09-17 변경) 새 그림책은 Book Print API 고화질 스퀘어북 하드커버 `SQUAREBOOK_HC`(PUR, 재단 243 × 248mm) 한 가지로 고정한다. 생성 전 모양 선택과 편집 중 모양 변경을 제거한다. 이유: 사용자 첨부 상품과 같은 규격으로 제작사에 PDF를 제출하기 위해서다. 기존 저장 책은 배치 보존을 위해 원래 비율로 읽고, 인쇄 시 지정 판형 안에 비율을 유지해 담는다.
6. 그림의 이동·크기 변경·회전·스냅 상호작용은 MIT 라이선스의 `react-moveable`을 사용하고 라이선스 고지를 저장소에 둔다. 그림책 문서와 이미지 소유권·저장은 Wiggle의 학생 세션, Turso, R2 경계를 그대로 따른다.
7. 편집기는 페이지 추가·복제·순서 이동, 그림 앞뒤 순서·잠금·투명도, 실행 취소·다시 실행, 캐릭터 배경 오리기, 미리보기와 저장을 제공한다.
8. 학생 홈의 확정된 3개 큰 메뉴 순서는 유지하며, 그림책 작업실은 그 아래의 별도 그림책형 카드와 완성 작품 상세의 `이 그림으로 그림책 만들기` 행동으로 진입한다.
9. (2026-09-23 변경) 그림책 목록·편집·교사·관리자 등 후속 화면에도 `ux-wiggle-web-2026-08-31/DESIGN.md`를 적용한다. 이전 책 팀의 독립 시각 기준은 종료한다. 첫 화면부터 학생 입장·그리기까지는 현재 디자인을 그대로 유지한다. 이미 기준에 맞는 화면 구성과 기능은 보존하며 색·글자·모서리·그림자·터치 크기 등 불일치만 수정한다.
10. 학생이 그림책에서 `완성하기`를 누르면 그 학급의 교사는 완성 그림책 목록에서 동물·별명, 완성 시각, 쪽 수를 확인하고 책 전체를 넘겨 보거나 브라우저 인쇄의 `PDF로 저장`을 사용할 수 있어야 한다(2026-08-27 사용자 결정).
11. 교사는 완성 그림책을 체크박스로 여러 권 골라 한 번에 피드백을 요청하거나 한 권씩 요청할 수 있다. 루브릭이 확정되기 전에는 AI 피드백을 임의 생성하지 않고 요청만 `루브릭 대기` 상태로 보존한다(2026-08-27 사용자 결정).

## 교사와 메시지

1. 교사는 전체 학급 또는 특정 학생에게 텍스트 도움말을 보낼 수 있다.
2. 학생은 닫은 교사 메시지를 다시 확인할 수 있어야 한다.
3. 교사가 학생 작품을 보고 있을 때 학생 화면에 이를 알린다.
4. 음성은 후속 단계이며 텍스트를 기본 수단으로 유지한다. (2026-09-09 사용자 지시) 학생 화면의 브라우저 읽어 주기(들어 보기) 버튼은 전부 제거했다. 교사 목소리 귓속말은 (2026-09-14 사용자: "음성 귓속말 기능 코드는 아예 제거해줘") API·검증·학생 표시·릴레이 연결까지 코드째 지웠다. 외부 중계 서비스가 필요했고 기본값이 꺼져 있어 쓰인 적이 없다.
5. (2026-09-14 사용자 결정) 선생님이 그리는 중인 아이 도화지에 관여하는 방식은 자유 채팅이 아니다. 선생님 표시(동그라미·화살표·짧은 글)는 점선·시범처럼 아이 원본 그림과 **따로 된 층**에 올리고 저장 그림에 합성하지 않는다. 사용자: "1번은 따로 된 층을 추천해주고". 이유: 3~6학년이 글자를 치면 그리기가 멈추고, 선생님 한 명이 여러 대화를 동시에 잇기 어렵고, 그림 조언은 위치를 가리켜야 전달된다. 제안 순서는 ① 원본 크기 거의 실시간 보기 ② 따로 된 층 표시 ③ 아이는 큰 버튼으로 답하기 ④ 아이가 먼저 손들기. 네 가지 모두 2026-09-14에 만들었다. 운영 규칙: 아이 화면에는 답하지 않은 최신 표시 하나만 뜨고, 완성한 그림에는 보내지 않는다. 손은 표시·그 아이 메시지·선생님 손 내리기·아이 스스로 내리기로 내려가고 10분 지나면 사라진다(Claude 판단 — 필요하면 사용자와 조정). (2026-09-14 사용자: "1번으로 진행해줘") 실시간 보기 지연은 선생님이 보고 있을 때만 줄인다 — 아이 자동 저장을 멈춘 뒤 0.5초·길어도 2초, 선생님 확인을 1초로. 보지 않을 때 저장 간격은 그대로다. 새 선만 따로 보내기·실시간 연결은 교실에서 느리다고 느낄 때 다음 단계로 둔다.
7. 7-4. (2026-09-28 사용자 요청) **엑셀·CSV 불러오기와 양식 내려받기는 학급을 만들 때도 쓴다.** 만든 뒤 학생을 더하는 화면에만 있던 것을 새 학급 만들기 폼에도 둔다 — 두 화면이 `RosterEditor` 한 컴포넌트를 함께 쓰므로 불러오기·붙여넣기·번호 자동 채움·오류 문구가 양쪽에서 같다. 파일은 여전히 교사 브라우저 안에서만 읽고 서버로 보내지 않는다.
7-3. (2026-09-20 사용자 결정: "각자 칸의 번호칸 이름칸 나눠서 적도록") 명단에 학생을 추가하는 화면은 **번호 칸과 이름 칸을 줄마다 따로** 받는다. 한 칸에 `1 김민준`처럼 몰아 적던 텍스트 상자는 없앤다 — 어디까지가 번호인지 선생님이 매번 확인해야 했다. 번호는 기존 명단의 마지막 번호 다음부터 자동으로 채워 두고 고칠 수 있으며, 마지막 줄에 이름을 적으면 다음 줄이 저절로 열린다. 엑셀·CSV 파일 불러오기와 표 붙여넣기는 그대로 두고, 읽은 결과를 칸에 펼친다(번호가 없으면 앞 줄 다음 번호로 채운다). 저장 경로와 서버 검증은 바뀌지 않는다.
7-2. (2026-09-12) 참여 코드표는 **브라우저 인쇄**로 나간다. 팝업 창을 새로 열지 않는다 — 1장은 실명이 있는 선생님 보관용, 2장은 잘라 나눠 줄 쪽지(반 QR·수업 코드·내 참여 코드)다.
7. 교사가 학급을 만들 때 명단(번호 + 실명)을 직접 입력하고, 만든 뒤에도 학생을 추가·제거할 수 있다(2026-09-07 사용자 결정, P-001 확정). 학생은 수업 코드나 학급 QR로 들어와 ~~자기 번호를 입력하고 그림 비밀번호로 본인을 확인한 뒤~~ 자기 참여 코드 6자리를 넣고 자기 창을 연다(2026-09-09 변경, `학생 입장과 기록` 4번). 명단은 학생 화면에 보여 주지 않는다 — 수업 코드를 아는 사람에게 반 전체 실명이 노출되기 때문이다. 명단·설정 탭은 자리마다 참여 코드를 보여 주고 복사·새로 뽑기·코드표 인쇄를 제공한다.
8. (2026-09-07 확정) 자기 등록 입장 흐름 — `새로 시작하기 / 내 그림 이어가기` 갈림길, 별명·동물로 프로필을 찾던 재입장, 중복 프로필 허용(`allowDuplicate`) — 은 **대체가 아니라 제거**다. 명단이 없는 학급에서 아이가 스스로 프로필을 만드는 예비 경로를 남기지 않는다. 이유: 두 경로가 공존하면 같은 아이가 명단 자리와 자기 등록 프로필 둘로 갈라져, 교사 화면의 번호와 실제 작품 주인이 어긋난다. 명단이 아직 없는 학급의 학생 화면은 "아직 준비 중이에요"에서 멈추고 선생님을 부르게 한다(`NO_ROSTER`).
9. 교사 학급 상세는 **오늘 수업 / 작품·그림책 / 명단·설정** 세 탭으로 나눈다(2026-09-09 사용자 선택). 오늘 수업은 현재 회차 학생 그림을 큰 썸네일 격자로 보여 주고 회차 변경·수업 안내·전체 메시지만 상단 행동으로 둔다. 작품 탭은 학생·회차 필터와 완성 그림책 진입을 맡고, 명단 탭은 학생 추가·수정·삭제/복원과 입장 코드·QR·가족 링크·학급 삭제를 맡는다. 이유: 수업 중 확인과 평소 관리 행동이 한 화면에 섞여 있던 복잡도를 줄이기 위해서다.
10. 오늘 수업의 학생 그림은 현재 학급에 열린 회차와 같은 `arcId + episodeId` 작품만 표시한다. 회차가 없을 때만 학생별 최근 작품임을 화면에 명시한다(2026-09-09 사용자 선택을 구현하며 확정). 다른 회차에서 나중에 저장한 그림을 오늘 그림으로 보이면 교사가 현재 수업 상황을 잘못 판단하기 때문이다.
